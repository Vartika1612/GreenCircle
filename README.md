## 📌 About the Project

**GreenCircle** is a production-grade farm-to-table marketplace that enables local organic farmers to list and sell their products directly to nearby customers — eliminating the middleman and keeping food local.

This project was built as a full-stack portfolio application to demonstrate real-world backend engineering skills: **role-based access control**, **stateless JWT authentication**, **relational data modelling**, **transactional order processing**, and **containerised deployment** — all wired together without frameworks doing the heavy lifting invisibly.

### Why this project?

Most e-commerce tutorials stop at a CRUD todo app. GreenCircle goes further:

- **Two distinct user roles** (FARMER, CUSTOMER) with isolated permissions enforced at both the route and service layers
- **Atomic stock management** — orders decrement product stock inside a DB transaction with row-level locking (`SELECT ... FOR UPDATE`) to prevent overselling under concurrent requests
- **Aggregate analytics** — the farmer dashboard computes revenue, active listings, and order counts via SQL aggregates (`COUNT DISTINCT`, `SUM`) rather than fetching everything into memory
- **Database-agnostic design** — SQLite for instant local dev, MySQL for production; switching requires only a single env-var change
- **Auto-generated OpenAPI docs** — FastAPI produces interactive Swagger UI at `/docs` with no extra code

## 🏗️ Architecture Overview

```
┌─────────────────────────────────────────────────────────┐
│                     React SPA (Vite)                    │
│  Auth Context · Product Listings · Order Flow · Dashboard│
└────────────────────────┬────────────────────────────────┘
                         │ HTTPS  (Bearer JWT)
                         ▼
┌─────────────────────────────────────────────────────────┐
│              FastAPI (Python 3.12 · Uvicorn)            │
│  ┌──────────┐  ┌────────────┐  ┌────────┐  ┌────────┐  │
│  │  /auth   │  │ /products  │  │/orders │  │/farmer │  │
│  └──────────┘  └────────────┘  └────────┘  └────────┘  │
│                                                         │
│  auth.py (JWT + bcrypt)  ·  Pydantic schemas            │
│  SQLAlchemy ORM  ·  Dependency Injection (Depends)      │
└────────────────────────┬────────────────────────────────┘
                         │ SQLAlchemy
                         ▼
            ┌────────────────────────┐
            │  MySQL 8 (prod)        │
            │  SQLite   (local dev)  │
            └────────────────────────┘
```

**Request lifecycle:**
1. React sends `Authorization: Bearer <JWT>` with every authenticated request
2. FastAPI's `get_current_user` dependency validates the token and resolves the `User` ORM object
3. Role-specific dependencies (`require_farmer` / `require_customer`) reject mismatched roles with `403`
4. Route handlers perform business logic through SQLAlchemy and return Pydantic-validated responses

## 🔑 Key Technical Decisions

### 1. Dependency-injection auth guards
Instead of middleware, auth is enforced per-route via `Depends()` chains:
```python
# Any route can compose these:
def require_farmer(user: User = Depends(get_current_user)) -> User:
    if user.role != UserRole.FARMER:
        raise HTTPException(403, "Farmer role required")
    return user
```
This makes permissions explicit, testable, and composable.

### 2. Atomic stock management with row-level locking
```python
product = db.query(Product).filter(...).with_for_update().first()
# ↑ acquires a row lock — concurrent orders cannot oversell
product.stock -= item.quantity
```

### 3. Database-agnostic via a single env var
| Environment | `DB_URL` |
|---|---|
| Local dev | `sqlite:///./greencircle.db` (default) |
| Docker | `mysql+pymysql://greencircle:pass@db:3306/greencircle` |
| Production | `mysql+pymysql://user:pass@planetscale-host/greencircle` |

### 4. Price snapshotting at order time
`OrderItem.price` stores the product price **at the moment of purchase** — so changing a product's price later never retroactively affects historical orders.

## 🚀 Quick Start

### Option A — Docker Compose (full stack, MySQL)

```bash
git clone https://github.com/Vartika1612/GreenCircle.git
cd GreenCircle

docker-compose up -d          # starts MySQL + FastAPI

cd frontend
cp .env.example .env.local    # set VITE_API_BASE_URL=http://localhost:8080
npm install && npm run dev    # → http://localhost:5173
```

### Option B — Without Docker (SQLite, zero DB setup)

```bash
# Backend
cd backend
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS / Linux

pip install -r requirements.txt
uvicorn app.main:app --reload --port 8080
# API:  http://localhost:8080
# Docs: http://localhost:8080/docs   ← interactive Swagger UI

# Frontend (new terminal)
cd frontend
npm install && npm run dev    # → http://localhost:5173
```

> On first run with SQLite, the database is created and seeded with demo farmers, products, and credentials automatically.

## 🧠 Engineering Highlights

| Area | What was built | Why it matters |
|------|---------------|----------------|
| **Role-based auth** | Composable `Depends()` guards — `get_current_user` → `require_farmer` / `require_customer` | Permissions are explicit per-route, easy to unit-test, no hidden middleware magic |
| **Atomic transactions** | `SELECT FOR UPDATE` row-lock during order creation; stock decremented inside a single DB transaction | Prevents race conditions and overselling under concurrent load |
| **SQL aggregates** | Dashboard stats use `func.count(distinct(...))` and `func.sum(...)` — no in-memory computation | Scales to large datasets; single round-trip to the DB |
| **Price snapshotting** | `OrderItem.price` captures the price at checkout, not a foreign key | Historical orders remain accurate if a farmer later edits pricing |
| **Pydantic v2 schemas** | Strict input validation + serialisation on all 13 endpoints | Eliminates an entire class of runtime bugs; auto-documents the API |
| **DB portability** | SQLAlchemy `with_variant` makes models work on both SQLite and MySQL | Zero-setup local dev with production-parity data structures |
| **OpenAPI docs** | Auto-generated by FastAPI — zero maintenance, always accurate | Interview-ready: live API explorer at `/docs` |
